# Summary

Added a mention-reply feature: when a user @mentions the bot directly, Raeon
replies with a friendly greeting embed pointing them to `/commands`.

# Files Touched

- `src/infrastructure/discord-client.ts` — added `GatewayIntentBits.MessageContent`.
- `src/handler/message.ts` — implemented `handleMessage`; added `client` to `MessageCommandServices`.
- `src/main.ts` — passed the Discord client into the `messageCreate` handler.

# Previous Behavior

`handleMessage` only filtered out bot authors and returned; the bot ignored
all user messages. The gateway had no `MessageContent` intent.

# New Behavior

On `messageCreate`, after the bot-author filter, the handler resolves
`client.user` and checks `message.mentions.has(clientUser, { ignoreEveryone,
ignoreRoles, ignoreRepliedUser })`. A direct @mention triggers a reply with an
info embed (`EmbedService.createInfoEmbed`) greeting the user and directing
them to `/commands`. Broad mentions (@everyone, role pings, reply pings) are
ignored.

# Reason For Change

Give users a discoverable entry point: pinging the bot surfaces the command
list instead of silence.

# Risks

- `MessageContent` is a privileged intent — must be enabled in the Discord
  developer portal or the gateway connection will fail. No code-level risk.
- Reply is fire-and-forget; a send failure (missing perms) rejects the
  promise but is contained to this handler.

# Notes

`npm run build` (strict tsc) compiles clean. Not exercised live against a dev
guild.

# Summary

Added two utility slash commands: `/about` (bot metadata) and `/usage`
(runtime resource usage).

# Files Touched

- `src/commands/about.ts` — new `aboutCommand`; reads `package.json` version at
  runtime via `import.meta.url`, defers then follows up with the about embed.
- `src/commands/usage.ts` — new `usageCommand`; defers then follows up with the
  usage embed.
- `src/infrastructure/embed.ts` — added `createAboutEmbed(client, version)` and
  `createUsageEmbed()` plus private `formatUptime` / `formatBytes` helpers.
- `src/main.ts` — imported and registered both commands in `slashCommands`.

# Previous Behavior

No way to query bot metadata or resource usage from Discord.

# New Behavior

- `/about` — embed (ACCENT) with name/version (from `package.json`), creator,
  GitHub repo link, server count (`client.guilds.cache.size`), uptime
  (`client.uptime`), and a short description. Bot avatar as thumbnail.
- `/usage` — embed (INFO) with heap memory (`process.memoryUsage()`), uptime
  (`process.uptime()`), platform/arch (`process.platform` / `process.arch`),
  and Node version (`process.version`).

Both follow the `commands.ts` pattern: `deferReply` then `followUp`.

# Reason For Change

Give operators and users an in-Discord view of bot identity and health.

# Risks

- Version is read from `package.json` at runtime relative to the compiled
  module (`../../package.json`). A static JSON import is not used because
  `package.json` lives outside `rootDir` (`./src`) and would trip tsc (TS6059).
  Path holds for the `dist/commands/*.js` layout; would break if the build
  output structure changes.

# Notes

`npm run build` (strict tsc) compiles clean. Not exercised live against a dev
guild. Existing behavior (including the `/commands` help embed) left untouched.
