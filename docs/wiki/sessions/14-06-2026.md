# Summary

Added a mention-reply feature: when a user @mentions the bot directly, Raeon
replies with a friendly greeting embed pointing them to `/commands`.

# Files Touched

- `src/infrastructure/discord-client.ts` — added `GatewayIntentBits.MessageContent`.
- `src/handler/message.ts` — implemented `handleMessage`; added `client` to `MessageCommandServices`.
- `src/main.ts` — passed the Discord client into the `messageCreate` handler.

# Previous Behavior

`handleMessage` only filtered out bot authors and returned; the bot ignored
all user messages. The gateway had no `MessageContent` intent.

# New Behavior

On `messageCreate`, after the bot-author filter, the handler resolves
`client.user` and checks `message.mentions.has(clientUser, { ignoreEveryone,
ignoreRoles, ignoreRepliedUser })`. A direct @mention triggers a reply with an
info embed (`EmbedService.createInfoEmbed`) greeting the user and directing
them to `/commands`. Broad mentions (@everyone, role pings, reply pings) are
ignored.

# Reason For Change

Give users a discoverable entry point: pinging the bot surfaces the command
list instead of silence.

# Risks

- `MessageContent` is a privileged intent — must be enabled in the Discord
  developer portal or the gateway connection will fail. No code-level risk.
- Reply is fire-and-forget; a send failure (missing perms) rejects the
  promise but is contained to this handler.

# Notes

`npm run build` (strict tsc) compiles clean. Not exercised live against a dev
guild.
