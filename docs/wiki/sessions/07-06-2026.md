# Summary

Lavalink migration L2: playback cutover. `GuildPlayer` rewritten as a
queue orchestrator around a Lavalink player reached through a new
domain-owned `PlayerPort` interface (keeps the domain dependency-free
per AGENTS.md); `infrastructure/lavalink.ts` gained the Shoukaku player
adapter plus `join`/`leave`/`resolveTrack`. The track `end` event now
drives auto-advance (F-6 fixed structurally), pause/resume are native
(position preserved — kills the resume-restarts-track constraint and a
latent bug where pausing dropped the player to IDLE), and the 300s
playback ceiling is gone (F-7). Multi-guild routing is structurally
correct (players keyed per guild).

# Files Touched

- `src/domain/track.ts` — new: `Track { encoded, title, author,
  duration, uri }`
- `src/domain/guild-player.ts` — rewritten: `PlayerPort` +
  end-event-driven queue; `skip()` (advance) vs `stop()` (halt, queue
  survives); exception handling deliberately rides the `end(loadFailed)`
  that follows fatal exceptions (non-fatal ones leave the track playing,
  so advancing on `exception` would double-advance or skip a live
  track; hangs surface as `stuck`); `stuck` force-stops since no `end`
  follows
- `src/infrastructure/lavalink.ts` — `ShoukakuPlayerAdapter`
  (exception/stuck/closed logging + stream-failure metric),
  `join` (shardId from guild cache, deaf), `leave`, `resolveTrack`
  (track/search/playlist → first track; error → `LavalinkError`;
  empty → null)
- `src/application/services/music.service.ts` — ctor now
  `(lavalink, extractor, onTimeoutNotification?)`; `play()` resolves
  via REST internally (deviation: plan wanted the Track in the
  signature at L2, but that breaks "commands untouched" — signature
  change lands at L3 with the commands); new `skip(guildId)`; all
  getters map Track→uri so embeds/presence stay byte-identical; queue
  cap 20 + idle timeout unchanged
- `src/main.ts` — drops `FfmpegEncoder`/`VoiceGateway` wiring;
  extractor kept solely for `/search` + ytsearch until L3
- `src/commands/skip.ts` — `music.stop()` → `await music.skip()` (the
  F-6 fix; `skip` is in the plan's target MusicService surface)

# Previous Behavior

Playback spawned yt-dlp→ffmpeg into @discordjs/voice; skip halted
without advancing; resume restarted tracks; 300s ceiling; multi-guild
voice unreliable.

# New Behavior

Lavalink node streams audio; bot only orchestrates queues. Skip
auto-advances, resume keeps position, no track ceiling. Old pipeline
files still on disk but unwired (deleted at L4); `/search` and the
ytsearch path still use yt-dlp until L3.

# Reason For Change

lavalink-plan.md phase L2 (cutover).

# Risks

- Live exit criteria (/play, /pause→/resume position, /skip advance,
  two-guild) not verified — no token/binaries here. Verified instead:
  tsc strict clean; GuildPlayer state machine smoke vs stub port (7/7:
  advance, skip-vs-stop, pause keeps track, loadFailed advance, restart
  after stop); real REST `loadtracks` against the running node returned
  search results with full metadata (youtube-source works end-to-end).
- Revert point: this commit starts the cutover band (L2–L4).

# Notes

`/stop` already used `disconnect()` (not `stop()`), so `stop()`'s only
caller was skip.ts — surface kept anyway. Presence still spawns
`yt-dlp --get-title` until L3.
