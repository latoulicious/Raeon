  extractor kept solely for `/search` + ytsearch until L3
- `src/commands/skip.ts` — `music.stop()` → `await music.skip()` (the
  F-6 fix; `skip` is in the plan's target MusicService surface)

# Summary

Drafted the persistent queue plan
(`docs/wiki/persistent-queue-plan.md`, phases Q0–Q3): the queue
survives bot death via a `guild_sessions` table (raw SQL on the
existing pg driver, no ORM, table auto-created at boot like `logs`).
Design decisions taken with the user at drafting: lazy restore (boot
loads sessions into memory; playback waits for the next `/play` or
`/resume`), interrupted track restarts from 0:00 (no position

graceful shutdown preserves the session (only `/stop` and idle timeout
clear it). The lazy + from-zero combination means `PlayerPort` needs
nothing new; `GuildPlayer` gains one additive `onChange` callback in
the same shape as U2's `onTrackFailed`.

sink only" constraint gets rewritten at Q3 (user approved the feature
